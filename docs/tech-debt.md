# 已知问题、占位与未验证项

按“影响”排序。新发现的问题记在这里，不要悄悄改行为。

## 未验证（重要）
- **本次重构是在无法联网安装依赖的环境里完成的**：真实的 `electron` / `electron-vite` / `better-sqlite3` / `sharp` / `sass` / React 类型都没有安装过。
  类型检查对的是手写的桩类型，**没有对真实库类型检查过**；构建（`npm run build`）、打包、`npm run dev` 都没有运行过。
  已做的验证：`check:*` 脚本、95 个单元测试、用 esbuild 打包渲染进程并在无头 Chromium 里用模拟 API 点击冒烟（无 JS 报错）。
  **接手第一件事：`npm install && npm run check && npm run dev`，把发现的问题修掉。**
- 没执行过任何真实 SQL（迁移原文照搬旧版，但仓库层和查询层是重写的，只有拼装逻辑的单元测试）。
- `sharp` / `exifr` 的动态导入在打包后能否工作未验证（`externalizeDepsPlugin` 应保持它们为外部依赖，但没实测）。
- SCSS 样式没有编译过，视觉未核对。

## 测试缺口
- 无界面自动化测试、无 Electron 端到端测试、无数据库迁移/仓库集成测试、无 bridge 测试。
- 无 CI 配置、无自动签名/更新。

## 占位与未完成
- 主进程里仍有写死的中文文案（对话框、系统通知、下载结果），应迁到 i18n（保持了旧行为，未改）。
- `DuplicateNotice`（重复提示）里的数量是占位值 3（沿用旧代码）。
- “删除”操作目前是 no-op（旧代码如此）；`deleteSmart` 接口已有但界面未使用。
- 侧边栏仍使用原生右键菜单（`Menu.popup`），尚未迁到自绘的 `shared/ui/Menu`。
- “维护”页的扫描结果在切换设置分类后丢失（旧版会保留）。
- 在浏览器里用模拟数据调试时，加载 `tessera://` 图片会出现 `ERR_UNKNOWN_URL_SCHEME`（只影响调试模式）。

## 设计上的已知限制
- FTS 搜索用 trigram，查询词需 ≥ 3 个字符。
- 中文文件名排序按 Unicode 编码而非拼音。
- 移动文件的撤销只保留最近一次，且重启即失。
